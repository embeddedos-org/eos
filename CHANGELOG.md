# Changelog

## [Unreleased]

### Security
- **`eos_acl_add_rule()` refuses a subject, resource or permission too long for its field instead of truncating it.** The fields were copied with `strncpy()` and the rule stored anyway, but `eos_acl_check()` compares whole strings, so the stored rule named something other than what the caller wrote: a DENY on a resource of 256 or more characters never matched (and the call returned 0), and an ALLOW on one granted access to the different, shorter resource its 255-character prefix spelled. Such calls, and NULL arguments, now return -1 and add nothing, as `eos_keystore_add()` already does for an overlong ID (#209). `tests/test_security.c` covers each field at one byte too long, the longest value that fits, and the prefix grant. **Contract change:** these calls used to return 0.
- **The Ed25519 arithmetic that verifies package signatures has no undefined behaviour left on its tested paths.** The ref10 field and scalar code in `services/crypto/src` reduced limbs with `carry << 25` (and `<< 26`, `<< 21`) on signed values that are negative about half the time, packed bytes in `fe_tobytes()` with `int32_t` shifts that overflow, and computed `babs` in `ge.c`'s `select()` by shifting a negative `signed char`. All three are undefined in C, so a compiler is entitled to miscompile the verifier, and under `-fsanitize=undefined` five suites aborted (`test_crypto_ed25519_loworder`, `test_ed25519_contract`, `test_pkg_anchor_usable`, `test_pkg_trust_anchor`, `test_pkg_install_paths`). Each shift is now a multiplication by the same power of two, or a shift of the value cast to `uint32_t`, which is what two's-complement hardware computed anyway, so the results do not change. No output change was observed: the new `tests/test_ed25519_rfc8032_kat.c` pins key generation and signing to RFC 8032 section 7.1 byte for byte, and passes against both the old and new code at `-O3`. Before this change nothing pinned the signer's output; the package tests only round-tripped their own signatures.
- **`eos_fetch_source()` no longer lets a URL or destination directory reach the shell.** Both are interpolated inside double quotes into `git clone`, `wget`/`curl`, `tar` and `unzip` lines run by `system()`. The deny-list did not include `"`, so a URL such as `https://host/x"<newline>touch pwned<newline>"y.tar.gz` closed the quote and ran a command before any digest was compared; `dest_dir` was not checked at all. `is_url_safe()` now also refuses `"`, `\`, control characters and a leading `-` (option injection), plus `%` on Windows, and is applied to `dest_dir`. A URL that is neither git nor a recognised archive used to fall through to a download-and-extract path that compared no digest; it is now refused with `EOS_ERR_INVALID`. `tests/test_pkg_fetch.c` asserts the injected command's marker file is never created. The real fix is to stop using a shell here (`eos_exec_argv()` lives in `cmd/eos` and is not reachable from `pkg`); this closes the demonstrated holes without that move.
- **`eos_storage_load()` validates the store file.** A negative item count passed the `count > MAX` clamp and the next `eos_storage_set()` wrote to `items[-1]` (heap overflow, reproduced under ASan); an item with `value_len` above `EOS_STORAGE_MAX_VALUE` or an unterminated key made `eos_storage_get()` read past the item. A file with a bad count, a bad item or a short read is now rejected whole: the call returns -1 and leaves `count` at 0. **Contract change:** an oversized count used to be clamped and loaded.
- **The file-based updater's verify (`services/os`, now `eos_ota_update_verify()`) fails closed.** With no expected hash it returned 0 for whatever was downloaded. It now returns -1 and sets `EOS_OTA_FAILED`. **Contract change:** callers must pass an expected hash to `eos_ota_set_source()`.
- **Build backends no longer hand configuration to a shell unchecked, and never run a truncated command.** All eleven backends under `backends/` built their `system()` lines with `snprintf` from the project's `src_dir`, `build_dir`, `install_dir`, toolchain and option values, quoted but unfiltered: a value carrying `"; touch pwned; "` ran as shell (reproduced against the CMake backend's `clean`), and `freertos_install`, `cargo_install` and `nuttx_install` formatted three `EOS_MAX_PATH` paths into a 1024-byte buffer, so a long path ran a cut-off line. Commands are now assembled through `EosShellCmd` (`core/include/eos/shell_cmd.h`): program text written in the tree is appended as text, every configuration value goes through `eos_shell_cmd_arg()` (double-quoted, refused if it carries a shell metacharacter or control character) or `eos_shell_cmd_word()` (unquoted, an allowlist of one word), and a line that does not fit or carries a refused value is refused with `EOS_ERR_INVALID` before anything runs. Option values are quoted, so a value with a space is one argument. The two rules are the ones `linux_security` reviewed and shipped, moved to `core` and used by both; `linux_security`'s own predicates delegate to them. `eos_shell_cmd_run()` reports a shell that could not be started, or a command the shell could not run at all (exit 127), as `EOS_ERR_SYSTEM` rather than as the `EOS_ERR_BUILD` a genuine build failure produces. `tests/test_shell_cmd.c` covers the rules, the builder, and every backend against a hostile directory.

### Changed
- **The RTC timestamp and the EoS POSIX `timespec` are 64-bit (T64 slice 1, #269).** `eos_rtc_get_unix_timestamp()` returned `uint32_t`, so the wall clock wrapped in February 2106 (and in 2038 for any consumer holding it in a signed 32-bit `time_t`); EoS's own `struct timespec` declared `tv_sec` as `uint32_t`. The timestamp is now `uint64_t` (`hal/include/eos/hal_extended.h`, the STM32F4 implementation in `hal/src/hal_extended.c` now computes in 64-bit through the new `eos_rtc_time_to_unix()` helper, host stub in `hal/src/hal_extended_stubs.c`), and `struct timespec` is `int64_t tv_sec; int64_t tv_nsec;` (`services/posix/include/eos/posix_time.h`), the POSIX shape. The civil-to-Unix conversion itself is unchanged (still the simplified no-leap-year formula), and the 32-bit millisecond tick (`g_tick`) is unchanged — its redesign is a later T64 slice, so `clock_gettime()` values still wrap every ~49.7 days. `tests/test_posix_time.c` pins the 2038 boundary (a timestamp past `INT32_MAX`), a value past the old `UINT32_MAX` return, and the full 32-bit tick range round-tripping through `timespec`. **Contract change:** the `eos_rtc_get_unix_timestamp()` return type and the `struct timespec` field widths are public API.
- **`eos_task_delete(0)` and `eos_task_suspend(0)` return `EOS_KERN_INVALID`.** Handle 0 is the idle task and it is permanent: it is the task the scheduler falls back to when nothing else is runnable. This restores the scheduler contract #131 established and #130's replay rolled back -- `kernel/src/task.c` on master was #130's copy, in which the idle task could be deleted or suspended, `eos_task_create()` published a TCB to the scheduler before its stack existed, and `eos_schedule()` left `g_current_sp` pointing at the outgoing task. The file is #131's again, plus #130's `wake_armed` hunk.

### Fixed
- **The GDB stub no longer claims to set watchpoints it does not implement.** `handle_set_breakpoint()` and `handle_remove_breakpoint()` in `debug/src/gdb_stub.c` parsed the `Z`/`z` type and ignored it, so a write, read or access watchpoint (`Z2`/`Z3`/`Z4`) was stored as a breakpoint at that address and answered `OK`: GDB reported the watchpoint set, and it never fired. Types other than 0 (software) and 1 (hardware breakpoint) now get the empty reply the remote protocol defines for an unsupported type, so GDB says the watchpoint cannot be inserted. `tests/test_debug.c` covers types 2-4 for both packets and keeps 0 and 1 working.
- **A driver's `deinit` runs once per `init`, not on every teardown.** `eos_driver_deinit_all()` set each driver to `EOS_DRV_STATE_UNINIT` but called `ops->deinit` whatever the state, and `eos_driver_unregister()` did the same: a second `deinit_all()`, or the usual `deinit_all()` followed by `unregister()`, deinitialised every driver twice (a double free or double release for a driver whose `deinit` frees what `init` took), and a driver registered but never initialised was deinitialised anyway. Both now skip `deinit` for a driver in `EOS_DRV_STATE_UNINIT`; a driver whose `init` failed (`EOS_DRV_STATE_ERROR`) is still deinitialised, as before -- a failed `init` may have acquired something before it returned, so teardown must still give it the chance to release it. `tests/test_driver_recovery.c` counts the calls.
- **`eos_fs_write()` on an `EOS_O_APPEND` descriptor writes at the current end of the file again, and a relative `eos_fs_seek()` no longer overflows.** Both were fixed in #206 and #204, and both fixes and their tests were lost when #229 merged #197 from a branch cut before them: on master a second append descriptor opened before the first one wrote overwrote its data (`B` instead of `AB`), and `eos_fs_seek(fd, INT32_MAX, EOS_SEEK_CUR)` from position 1 overflowed `int32_t` and landed at 0 instead of clamping to the end of the block. `services/filesystem/src/filesystem.c` and `tests/test_filesystem.c` carry #204 and #206 again, together with #197's readdir terminator.
- **With a rotated display, the gesture recogniser gets screen coordinates too.** `eos_ui_touch_read_cb()` in `services/ui/src/ui_touch_drv.c` rotated only a copy of the first touch point, for LVGL, and fed the controller's unrotated points to `eos_ui_gesture_feed()`, although the file says both receive screen-space coordinates. With `EOS_UI_ROTATE_90`, `_180` or `_270`, gesture events carried panel coordinates in `start_x`/`start_y`/`end_x`/`end_y` and swipe directions were judged on the panel axes (at 180° a swipe to the right was reported as `EOS_GESTURE_SWIPE_LEFT`). Every point is now rotated before either consumer sees it. New suite `tests/test_ui_touch_drv.c`.
- **Deleting a blocked task removes it from every wait list.** `eos_task_delete()` left the task queued on mutexes, semaphores and queues, so `eos_mutex_unlock()` could grant the mutex to the dead task (every later locker blocked forever, or a task reusing the slot "owned" a lock it never took), the owner kept the dead waiter's priority boost, and a post or send could wake the dead task instead of a live waiter. Delete now purges the task (`eos_sync_forget_task()` / `eos_ipc_forget_task()`, internal) and re-derives the owner's inherited priority. A task deleted while it *owns* a mutex still leaves that mutex locked, as before.
- **A one-shot software timer can restart itself from its callback.** `eos_swtimer_tick()` cleared `active` after the callback returned, cancelling the restart. The timer is now re-armed or retired before the callback runs.
- **`eos.yaml` package keys are no longer lost after a `build:`, `deps:` or `options:` block.** `source:`/`hash:` after `build:` were dropped (the package lost its pinned digest silently), any key after a `deps:` list was dropped, a `deps:` after `options:` was interned as an option named `deps`, and `options:` directly under a package was ignored. A key at the package's own indent now returns to the package, as `system:` and `toolchain:` already did.
- **`eos_net_recv()` / `eos_net_recvfrom()` with `timeout_ms == 0` poll.** They skipped `SO_RCVTIMEO` for 0 but then blocked on the socket's default (forever) or on a timeout an earlier call had set. 0 now uses `MSG_DONTWAIT`.
- **`eos_dt_find()` handles a path component of `EOS_DT_NAME_MAX` characters or more.** It advanced by the truncated length, so the tail of a long node name was read as the next component.
- **`eos_driver_init_all()` initialises only `UNINIT` drivers and retries `ERROR` ones.** A second call (e.g. after a hot-plug register) re-ran `init` under an open device and reset it from `ACTIVE` to `READY`, after which `eos_driver_close()` refused it.
- **`eos_raid_rebuild()` bounds both disk ids** (an id past the array wrote outside it) **and RAID-6 usable capacity is 0 below three disks** (it wrapped to ~2^64 for one disk). New suite `tests/test_datacenter.c`.
- **Datacenter VM ids keep naming the same VM after another VM is destroyed.** `eos_vm_create()` returned the VM's slot index as its id, and `eos_vm_destroy()` packs the table, so every VM after the destroyed one moved down a slot: its old id then named the next VM (starting "vm-b" by its id started "vm-c"), and the next `eos_vm_create()` handed out an id a live VM still held. Ids now come from a counter in `EosVirtualization` (`next_id`, zeroed by `eos_vm_init()`) and are never reused; start, stop, pause, destroy and get look the id up. A new VM also no longer inherits the usage figures left in its slot. `tests/test_datacenter_vm.c` covers both cases.
- **A log line too long for its 256-byte buffer still ends in a newline.** `emit()` in `core/src/log.c` clamped the length after `snprintf()` truncated the line, but the `\n` was the part cut off, so the file and UART outputs ran that record and the next one together on one line. The last byte of a truncated line is now `\n`. New suite `tests/test_log.c`.
- **Semaphore and queue waits no longer time out under `EOS_WAIT_FOREVER`.** `eos_sem_post()` / `eos_queue_send()` / `eos_queue_receive()` dequeue and ready one waiter without reserving the count, item or slot for it, so a task that ran first could take it and the woken waiter returned `EOS_KERN_TIMEOUT` with no time limit having expired. A waiter that was woken (it is no longer on the wait list) but finds nothing now waits again for the remaining time; one still on the list timed out, as before. `tests/test_kernel.c` reproduces the stolen wakeup for all three.
- **`eos_task_create()` rejects a stack smaller than `EOS_MIN_STACK_SIZE` (128 bytes, overridable).** The port writes a 17-word initial frame below the stack top, so a smaller stack had that frame written over the previous task's saved context. `stack_size == 0` still selects 1024. **Contract change:** such calls now return `EOS_KERN_INVALID`.
- **`eos_pkg_install()` closed the package file twice** on its three error paths after the blobs are read (create-directory failure, binary not creatable, short write) and leaked the resource blob on them. The extra `fclose()` calls are gone and the blob is freed.
- **OTA A/B: the slot being written is not a rollback target.** After an A->B apply, slot A stayed marked valid while the next `eos_ota_begin()` overwrote it, so `eos_ota_rollback()` or `eos_ota_set_active_slot()` mid-download switched to a half-written image. `begin()` now clears the update slot's valid flag.
- **`eos build` / `system` / `firmware` / `hybrid` stop on package and firmware set-up errors.** Results of `eos_package_set_from_config()` (all four), `eos_package_resolve()` (system, firmware, hybrid) and `eos_firmware_init()` (firmware) were discarded, so a missing dependency or an over-long name built a partial set and exited 0, and a truncated firmware path was built into. They now go through `EOS_CHECK`.
- **Unterminated paths from `strncpy`:** `resolve_output_dir()` in `systems/src/docs.c` and the per-package `src_dir`/`build_dir` copies in `core/src/scheduler.c` copied into uninitialised stack buffers, so a path of exactly `EOS_MAX_PATH - 1` characters had no terminator. Both are terminated explicitly.
- **GDB stub: a packet of the advertised size is accepted, and a refused packet does not end the session.** `qSupported` announced `PacketSize=400` (1024 bytes) over a 512-byte receive buffer, so GDB was told it could send packets the stub then NACKed every time; and `recv_packet()` stopped reading at the buffer's end and took the next two body bytes for the checksum, leaving the stream out of step. The size is now derived from the buffer (`PacketSize=1ff`), a body that does not fit is drained to its `#` and refused with `-`, and the dispatch loop distinguishes a refused packet (GDB resends it) from a dead transport -- it used to exit on the first corrupt or oversized packet. The drain is bounded: a body that never reaches its `#` is abandoned after another `PacketSize` bytes with a `-`, where the first version of this change read it forever. The `m`/`M` memory cap is derived from the packet size too (`GDB_MEM_MAX`, 248 bytes) instead of a literal 128, so a bulk transfer GDB sizes from `PacketSize` is not answered `E01`. `tests/test_debug.c` covers a packet of exactly the advertised size, one 40 bytes longer, one with a bad checksum, a body that never ends, and an `M` one byte past the cap, each followed by a `D` that must still be answered; `tests/unit/test_gdb_stub_limits.py` pins the derivations in the source.
- **OTA download and install no longer go through a shell.** `eos_ota_download()` and `eos_ota_install()` in `services/os/src/os_services.c` built `wget -q -O "%s" "%s"` and `cp -f "%s" "%s"` with `snprintf` and handed them to `system()`, each behind its own denylist with its own holes: the URL's omitted `"` and `&`, so a URL carrying `" & <cmd> & "` ran the command and then reported a failed download; the target path's omitted the backtick, so a target of ``x`<cmd>` `` ran the command and reported `EOS_OTA_COMPLETE`. Both were demonstrated by execution in review. Neither step needs a shell: the fetch now runs `wget` (POSIX) or `curl` (Windows) with an argv through `posix_spawnp()` / `_spawnvp()`, and the install is a file copy in C. The only check left on the URL is what the downloader would do with it -- it must be `http://` or `https://` and made of RFC 3986 URL characters, so it cannot be read as an option or a local file. `tests/test_os_services.c` runs both probes as data and asserts the sentinel is never created. (#164)
- **Master did not compile after the 09-08 batch merge.** Nine PRs were merged within minutes, each on the base it was written against. #119 and #132 each added an `#else` to the same `#ifndef _WIN32` in `eos_busybox_install_to_rootfs()`, so `linux_security.c` read "#else after #else" and every C job, CodeQL and the simulation's ARM64 kernel failed to compile -- before the Python guards that would have named the rest could run. The duplicate arm is removed. Behind it: `test_linux_security_paths` (#119) and `test_pkg_fetch` (#115), whose `add_executable()` blocks later replays had overwritten, are registered again (41 to 43 suites); four `test_kernel` tests from #130 and #131 that were defined but never called are wired into `main()`; `windows-test` (#132) is in the CI gate's `needs`, so the gate cannot be green with the MSVC leg red; and `eosim-sanity.yml` and `simulation-test.yml` (#129), whose `pull_request` trigger is path-filtered and so cannot be a required check, are classified in `test_ci_gate.py`'s `NOT_REQUIRED`.
- **`eos_busybox_install_to_rootfs()` refuses `NULL`:** it read `bb->source_dir` to hand it to `is_path_safe()`, so a `NULL` `bb` was a crash rather than a -1. Both arguments are now refused before either is dereferenced.
- **`linux_security` shell commands:** `is_path_safe()` was a denylist of shell metacharacters that missed the backtick and the newline, was applied at 2 of the 9 call sites that build a command, and returned "safe" for `NULL`. A path of the form `/tmp/<backtick>id<backtick>` reached `system()` and ran `id`. The predicate now rejects control characters, backslash, backtick and newline, refuses `NULL`, and guards every shell-building entry point. `eos_busybox_configure()` validated `source_dir` *before* filling in its default, so the default path -- the one a caller gets by not setting the field -- validated the empty string and handed `.eos/build/src/busybox-<version>` to the shell unchecked; the fill now happens first, and `eos_busybox_set_version()` refuses a version that is not one shell word.
- **One shell word is an allowlist.** `defconfig` and `cross_compile` are interpolated unquoted. The predicate guarding them was a second denylist (space, tab, `*`, `?`, `~`) that missed `[`/`]` and `{`/`}`, and accepted a leading `-`. It is now `isalnum()` plus `._/+=:-` and nothing else.
- **Security steps no longer report success without having run.** `eos_ima_sign_file()`, `eos_selinux_install_to_rootfs()`, `eos_selinux_label_rootfs()`, `eos_ima_install_to_rootfs()` and `eos_busybox_install_to_rootfs()` ended their commands with `|| true` or `|| echo …` and discarded `system()`'s result, so a missing `evmctl` or `setfiles`, a failed policy or key copy, and a `make install` that never ran all returned 0. Each now distinguishes a step that completed from one that could not, logs through `EOS_ERROR` and returns -1. **Contract change:** these five functions previously always returned 0; no caller in this tree relies on that.
- **`eos_busybox_configure()` / `eos_busybox_build()`:** `offset += snprintf(...)` accumulated the would-be length, so a truncating segment would have put the write pointer past the end of the buffer and underflowed the remaining size. Unreachable at the current field widths; now checked rather than inferred.
- **`eos_pkg` trust anchor:** Package signatures were checked against `eos_pkg_public_key[32] = {0}`. #99 stopped that all-zero key accepting every package, which left it rejecting every package -- including correctly signed ones -- while reporting `signature verification failed`, blaming the package for a key that was never provisioned. The key now comes from `eos_pkg_set_trust_anchor()` or from `EOS_PKG_TRUST_ANCHOR_HEX` at build time; with neither, verification refuses and says so, unless the build defines `EOS_ALLOW_UNSIGNED_PKG`. Closes the second half of #98.
- **`services/pkg` is compiled.** `services/pkg/eos_pkg.c` was in no `CMakeLists.txt`, so no target built it and no test could reach it -- which is how the all-zero anchor survived. It is now the `eos_eapp` library, with `tests/test_pkg_trust_anchor.c` covering it.
- **`ed25519_public_key_is_usable()`:** #99's subgroup and identity checks are exported, so a stored trust anchor can be rejected when it is configured rather than once per package as an apparent signature failure.
- **`eos_queue_send` / `eos_queue_receive`:** A full send/recv waiter table now returns `EOS_KERN_NO_MEMORY` instead of blocking a task that can never be woken, matching mutex and semaphore behavior.
- **`eos_queue_create`:** Size check now uses division so `item_size * capacity` cannot wrap `size_t` on 32-bit targets and overflow the 1024-byte queue store.
- **`eos_sem_create`:** Reject `initial > max` and `max` values that do not fit in `int32_t`, so the counting-semaphore invariant cannot be created already broken.
- **`eos_mutex_lock`:** Recursive lock returns `EOS_KERN_FULL` at `uint8_t` saturation instead of wrapping `rec_count` to 0 and leaving the mutex stuck.
- **`eos_mutex_lock`:** A waiter that times out no longer leaves the mutex owner permanently boosted. The owner's effective priority is recomputed from its base priority and the remaining waiters, so the boost propagates transitively along the blocking chain and is withdrawn when a waiter leaves. A full waiter table returns `EOS_KERN_NO_MEMORY` without applying a boost.
- **`eos_dt_parse`:** Bounds-check the flattened device tree blob before dereferencing it. A malformed DTB could previously read outside the buffer four different ways: `off_struct` past the end of the blob (the `size - off_struct` bound wrapped), a node name with no terminator (unbounded `strlen`), a property name offset outside the strings block, and nesting deeper than the 32-entry node stack. All are now rejected.
- **`eos_dt_find_compatible`:** Search within `prop->len` instead of calling `strstr()` on a property value that is not guaranteed to be NUL-terminated.
- **`eos_dt_get_irq`:** Reject a negative index, and one large enough that `index * 4` overflows, before it is used as an offset.
- **`.eapp` header name fields are path components, not paths.** `eos_pkg_install()` wrote the binary to `apps_dir/<package_id>/<name>` with both fields taken raw from the header, which the signature does not cover (it signs the binary alone): a genuinely signed package with `package_id` of `../escape` installed a 0755 binary outside `apps_dir`, a 64-byte field with no terminator was printed and joined into paths past the end of the header struct, and since `eos_pkg_remove()` hands `install_path` to `rm -rf "..."` through `system()`, a quote in `package_id` reached a shell. `verify`, `install` and `update` now refuse a `name` or `package_id` that is not a terminated, non-empty string of `[A-Za-z0-9._-]` other than `.` and `..`; in `verify` the check runs after the signature so an unsigned package is still reported as unsigned; in `install` it runs before anything is printed; `update` validates the header it read itself and verifies before it looks the id up. The package database is held to the same rules on load: a record whose names are not names, or whose `install_path` is not the directory `install` builds, is dropped with a message rather than acted on, so a record an earlier version wrote from an unvalidated header cannot reach `remove` or `stop`. And nothing in `eos_pkg.c` reaches a shell any more: removal is a directory walk in C on directory descriptors (`unlinkat`/`openat` with `O_NOFOLLOW`, so nothing is checked and then trusted, and a symlink is removed rather than followed) that refuses a path other than the package's own install directory, and `stop` hands the name to `pkill`/`taskkill` as an argv element. Pinned by `tests/test_pkg_install_paths.c`.
- **A watchdog timeout under a second expires.** `eos_watchdog_start()`, `eos_watchdog_kick()` and `eos_watchdog_check()` in `services/os/src/os_services.c` timed the watchdog with `time(NULL) * 1000`, which only moves once a second: a 100 ms watchdog checked 300 ms after its last kick (within one second of `time()`) reported no expiry, and every timeout was out by up to a second. The watchdog now reads a monotonic millisecond clock: `CLOCK_MONOTONIC` where the C library has it, `GetTickCount64()` on Windows, and whole seconds of `time()` only on a target that offers neither. Monotonic throughout is deliberate -- a watchdog measures an interval, so a clock that can be set by NTP or an operator would expire a healthy system when it jumped forward and hide a hung one when it jumped back. `eos_watchdog_check()` also refuses to treat `now` below `last_kick` as elapsed time, so neither a backwards step of the `time()` fallback nor a kick landing between its two reads can wrap the unsigned subtraction into an immediate expiry. `last_kick` and `start_time` are milliseconds of that monotonic clock, with an unspecified origin -- only differences between them are meaningful, they are not Unix-epoch times and must not be formatted as dates (documented on `EosWatchdog`); the audit-log timestamps are unchanged. New tests in `tests/test_os_services.c`.

### Added
- **ESP32 Secure Boot V2 and flash encryption (development mode), rehearsed on QEMU.** `sim/qemu_esp32/secure_image.sh` signs an EoS image for the boot ROM's RSA-3072 check and encrypts it for 0x1000, writing nothing unless the signature verifies and the ciphertext decrypts back; `secure_burn.sh` burns the flash key, the signing key's digest, `FLASH_CRYPT_CONFIG`, `FLASH_CRYPT_CNT` and `ABS_DONE_1`, refusing a chip that is not rev3, not on the 256-bit coding scheme or already burned (checked against an emulated chip with `ABS_DONE_1` set), and needs `EOS_BURN_CONFIRM=burn-permanently` for a serial port; `secure_rehearse.sh` runs that same burn on QEMU's emulated eFuses and requires the ROM to boot the signed, encrypted image and refuse an unsigned, a tampered and an unencrypted one. A new CI step runs the rehearsal with keys made for the run. Release-mode eFuses (download-mode encryption/decryption/cache, JTAG, ROM console, `UART_DOWNLOAD_DIS`) are not burned, so the board stays reflashable and is not protected against someone with its USB port; the procedure and what is permanent are in `sim/qemu_esp32/README.md`. No board has been burned.
- **`printf` and `malloc` work on the ESP32.** `boards/esp32/syscalls_esp32.c` gives the toolchain's newlib its system calls: stdout/stderr to the UART0 console, `_sbrk` on the DRAM the linker leaves (`.heap` in `esp32.ld`), `__malloc_lock` on the kernel's critical section, `__getreent` (one shared reentrancy struct: errno is shared), `_exit` through a fatal report. The image links newlib-nano, as the Cortex-M targets do: full newlib's `printf` overflowed a 1024-byte task stack. The unmodified `ebuild` rtos-app template (producer/consumer with a queue, a mutex and `printf`) runs in QEMU and on the board, one line per 500 ms.
- **SMP: the kernel runs tasks on both ESP32 CPUs (`-DEOS_SMP_CORES=2`).** `kernel/src/task.c` keeps a current task, saved-SP slot and idle task per CPU; each CPU picks the best READY task it may run (new `eos_task_set_core_mask()`, `eos_task_get_cpu()`) that no other CPU is still executing. State changes that were unguarded on one CPU (`eos_task_suspend()`, `eos_task_resume()`, `eos_task_yield()`, `eos_task_get_current()`) now take the critical section, which the Xtensa port makes a recursive S32C1I spinlock shared by both CPUs. Each CPU has its own tick; time advances on CPU 0, and yields, unblocks and expired delays raise the other CPU's cross-CPU interrupt. The ESP32 board starts the APP CPU as ESP-IDF does. With `EOS_SMP_CORES` left at 1 no SMP code is compiled and the single-CPU behaviour is unchanged (host suite 68/68, Cortex-M4 build, all ESP32 single-CPU tests on QEMU and the board pass). `sim/qemu_esp32/smp_test.c` passes in QEMU (new CI step) and on the board: two racers pinned to different CPUs each saw the other mid-run (on the board tens of thousands of their unlocked increments were lost), a mutex-protected count exact, tasks created and self-deleted on both CPUs each ran once, migrating tasks' register and window checks clean, 1000 cross-CPU semaphore round trips in 60 ms, no task ever on two CPUs. **Contract change (SMP builds only):** `eos_task_t` gains `core_mask`, and handles 0 .. `EOS_SMP_CORES`-1 are the idle tasks. Not done: HAL drivers have no locks of their own, DPORT reads lack ESP-IDF's dual-CPU erratum workaround, and `kernel/src/multicore.c` remains an unconnected stub.
- **ESP32 touch pads, light sleep and deep sleep (board API).** `hal/src/hal_esp32/hal_esp32_touch.c` reads T0-T9 as ESP-IDF's legacy driver configures them; `hal_esp32_sleep.c` adds RTC-timer light sleep (returns after waking; the kernel tick stands still meanwhile) and deep sleep (wake-up is a reset; `EOS_ESP32_RTC_NOINIT` variables in RTC slow memory and the RTC timer carry over). Boot now runs the power-control part of ESP-IDF's `rtc_init()` and tunes the RC clocks: without it deep sleep reset the RTC controller and woke at once, and then never woke while the RTC fast clock came from the powered-down crystal (found by diffing every RTC_CNTL register against an ESP-IDF build's on the same board); the slow clock had been running untuned at about 357 kHz instead of about 150. `sim/qemu_esp32/rtc_test.c` passes on the board: every pad reads and is stable, T0 responds to its own pull-down, a 200 ms light sleep lasts 200 ms by the RTC timer with no CPU cycles counted, and a 1 s deep sleep wakes with reset reason 5, the timer as cause and RTC memory intact (1.001 s by host time). Finger detection needs a person and prints NOT RUN without one. `sim/qemu_esp32/board_suite.sh` runs every QEMU and board test.
- **ESP32 I2S audio.** `hal/src/hal_esp32/hal_esp32_i2s.c` implements the extended HAL's `eos_audio_*` on I2S0 (`-DEOS_ENABLE_AUDIO=1`): master, Philips framing, 16-bit, mono or stereo, 8-48 kHz, full duplex on shared BCK/WS, the CPU feeding the 64-word FIFOs. `bus_test.c` loops DOUT into DIN in the GPIO matrix on the board: the divider gives 8000 and 44099 Hz, WS and BCK counted on the pads are within 1% of fs and 32 x fs, 48 stereo and 24 mono samples come back in order, and volume 50% halves and mute zeroes them. Found on the board: when the FIFO runs dry the transmitter repeats its last word, so a played buffer left the line at its last sample (a DC offset); every buffer now ends with a zero frame and the test checks the line idles at 0. Without DMA, play and record do not overlap: a play of more than 64 words blocks while the receiver overflows (documented in `sim/qemu_esp32/README.md`).
- **ESP32 SPI and I2C drivers.** `hal/src/hal_esp32/hal_esp32_spi.c`: SPI2/SPI3 master, modes 0-3, 8-bit, chip select on a GPIO held for the whole transfer, any length through the 64-byte buffer, clock never above the request (ESP-IDF's nearest-divider rule would have run a 26 MHz request at 26.67 MHz) and at most APB/3. `hal_esp32_i2c.c`: I2C0/I2C1 master on ESP32 command lists, any length through END-command refills, controller reset after a NACK, lost arbitration or timeout; a polled slave as a board API. `sim/qemu_esp32/bus_test.c` passes on the board: SPI loopback on both ports for every mode and five clocks (CPOL checked from the pad; CPHA cannot be seen in a loopback), divider results, and I2C address matching and NACK recovery with the slave listening to the master's pads. I2C data transfers need two jumper wires (an I2C bus is a wired AND that two pads cannot form inside the chip, and the ESP32 master stalls when its SDA input does not follow its output); the test detects them and otherwise prints NOT RUN.

### Fixed (ESP32)
- **Pull-ups and pull-downs on the ESP32's RTC-capable pads work.** GPIO0, 2, 4, 12-15, 25-27 and 32-39 take their pulls from the RTC IO registers, and the backend set only the IO_MUX bits, which do nothing on those pads: `eos_gpio_init()` with a pull on, say, GPIO4 or GPIO33 left the pin floating (found when I2C1's pads on GPIO32/33 read low). The pulls are now written where the pad has them, as ESP-IDF's `gpio_ll_pullup_en()` does; `bus_test.c` reads pull-up and pull-down back on GPIO4, 33 and 23, and fails with the old code.

- **The ESP32 runs at 240 MHz.** The CPU stayed on the 40 MHz crystal the boot ROM leaves it on. `boards/esp32/board_esp32.c` now runs ESP-IDF's BBPLL sequence (480 MHz PLL, 1.25 V core for 240 MHz; 320 MHz and 1.10 V for 80/160) through the ROM's `rom_i2c_writeReg`, which the windowed ABI makes callable, lets UART0 drain, switches the clock and gives UART0 its divider for the 80 MHz APB. `EOS_ESP32_CPU_MHZ` (240, 160, 80 or 40) selects it and must match `EOS_SYS_CLOCK_HZ`; a crystal other than 40 MHz stops the boot with a message. The HAL's timeouts, UART settle time and the test delays now use the configured CPU clock instead of a hard-coded 40 MHz. On the board, 400 ms of ticks counted 96,000,928 cycles, host-timed heartbeats were 1.0000 s apart, and the scheduler, context (1474 rounds per task, against 240 at 40 MHz), fault and peripheral tests pass. `capture_serial.py`'s read timeout went from 50 ms to 2 ms: it had stamped some lines up to 50 ms late, which is where the earlier "1.004 s, 0.4% slow" came from.
- **The ESP32 port uses the windowed ABI.** It was built with CALL0 (`-mabi=call0`), which kept the context switch to one frame but made the boot ROM's functions, the toolchain's newlib and libgcc, and Espressif's binary libraries (Wi-Fi, Bluetooth, PHY) unlinkable. `kernel/src/arch/xtensa_lx6/vectors.S` now has the six window overflow/underflow handlers, and its level-1 handler saves the interrupted window in the frame and spills every older window to the task's stack before the dispatcher runs, then resets the window state when it restores a task; an alloca (MOVSP) exception takes the same spill and retries. The frame sits 16 bytes below the task's stack pointer so the spill of the caller's a0..a3 cannot overwrite it. A new task starts as if CALL4ed into its entry function. `boards/esp32/freestanding.c` is gone: the image links the toolchain's `-lc -lgcc`. `context_test.c` gained 24-deep recursions through CALL8 (C, through a volatile pointer so GCC cannot turn them into loops) and CALL4/CALL12 (assembly), checked against iterative references, and a fairness check; in QEMU, removing the spill, removing the 16-byte gap, or a wrong register in any of the CALL4/8/12 handlers fails it. On the HiLetGo board the scheduler, context (240 rounds per task, no errors), fault (`code=7`) and peripheral tests pass. **Contract change:** code linked into the ESP32 image must be built for the windowed ABI (`port.c` refuses `-mabi=call0`).
- **ESP32 `eos_adc_read_mv()` uses the chip's eFuse calibration.** It was a straight line to 3600 mV fitted on one board. `hal/src/hal_esp32/hal_esp32_adc_cal.c` ports ESP-IDF v5.4's line fitting (Apache-2.0; constants and lookup table are Espressif's): two-point values when BLK3_PART_RESERVE is burned, else the chip's measured Vref, else 1100 mV, plus the 12 dB lookup table above raw 2880. `eos_esp32_adc_cal_source()` reports which was used. `tests/test_esp32_adc_cal.c` compares it with ESP-IDF's own function compiled on the host (a full sweep of both units, 9-12 bits and seven eFuse settings matched exactly when written; 94 edge vectors are kept). One deliberate difference: ESP-IDF v5.4 leaves Vref at 0 for two-point chips, so its table returns falling voltages above 2880; the port uses the chip's Vref (a test checks the output does not fall, and fails when the defect is reintroduced). On the HiLetGo board (eFuse Vref 1107 mV) a 1650 mV DAC output now reads 1658 and 1666 mV.
- **ESP32 ADC, DAC, PWM and UART1/2 drivers, checked on a board.** `hal/src/hal_esp32/hal_esp32_analog.c` implements the extended HAL's `eos_adc_*` (ADC1 and ADC2, 9-12 bits, one-shot), `eos_dac_*` (GPIO25/26, 8-bit) and `eos_pwm_*` (LEDC high-speed channels 0-3, each on its own timer, 1 Hz-8.388 MHz), and the backend now configures UART1 and UART2 (300 baud-5 Mbaud, 5-8 data bits, parity, 1/2 stop bits) with a loopback hook for self-tests. The ESP32 channel numbering the portable API leaves open is in `sim/qemu_esp32/README.md`. A pin an ADC or DAC used is handed back to the digital mux by GPIO and peripheral routing; without that it stayed disconnected. `sim/qemu_esp32/periph_test.c` checks it all through loopbacks inside the chip (DAC into ADC2 on the same pad, ADC1 against the pad's own pull resistors, PWM sampled on its pin, every UART frame format on both ports at two baud rates) and passed on a HiLetGo ESP-WROOM-32; QEMU does not model these peripherals, so CI builds the test without running it. Three ESP32 UART behaviours, each reproduced on the board and matched against ESP-IDF, are handled: RX is read through the peripheral-bus FIFO address (the AHB alias returned wrong bytes), the FIFO reset bits are not used (toggling them made every second UART2 reconfiguration receive garbage; the RX FIFO is drained instead), and the receiver is left to go idle after a reconfiguration. ADC reads time out after 1 ms with `0xFFFFFFFF` instead of hanging.
- **ESP32 (Xtensa LX6) kernel port, verified on a real board.** `kernel/src/arch/xtensa_lx6/` (vectors, level-1 handler, context switch, CCOMPARE0 tick, software-interrupt yield), `boards/esp32/` (reset entry, linker script, watchdog disable, UART0 console, fatal report) and a GPIO/UART0 HAL backend selected with `-DEOS_HAL_BACKEND_ESP32` (`hal/src/hal_esp32/`). The ESP32 boot ROM loads the image straight from flash at 0x1000; nothing from ESP-IDF is linked. The port is built with the CALL0 ABI, so a context is one 96-byte frame and no register windows are spilled; the cost is that windowed binaries (newlib, libgcc, Espressif's Wi-Fi/BLE libraries) cannot be linked, and the image carries its own `memset`/`memcpy`. `sim/qemu_esp32/` builds one image for Espressif's QEMU `esp32` machine and for boards: `scheduler_test.c` passes only if tasks switch through the tick and the software interrupt and the LED pad follows every toggle; `context_test.c` has three never-blocking tasks check a0..a15, SAR and a zero-overhead loop while the tick preempts them, so a frame that loses any of them fails (checked by mutation: dropping the SAR or LCOUNT restore fails it, where the scheduler test still passed); and `fault_test.c` requires a returning task to stop the system with its own report, `EOS FATAL code=7`. The new `QEMU ESP32 Boot Test` CI job runs all three, with the toolchain and QEMU pinned to the SHA-256 sums ESP-IDF v5.4.2 records. On a HiLetGo ESP-WROOM-32 (ESP32-D0WD-V3) the scheduler test passed with no LED readback errors, the context test passed with no register errors, and 1000 ticks measured about 1.004 s of host time. The idle task now sleeps in `waiti 0` on Xtensa instead of spinning. Limits (one core, no Wi-Fi/BLE, no watchdog, GPIO and UART0 only) are listed in `sim/qemu_esp32/README.md`.
- `tests/test_posix_time.c` — 64-bit time (T64 slice 1, #269): the RTC civil-to-Unix conversion past the 2038 and 2106 boundaries, the widened `timespec` holding values past `UINT32_MAX`, and the full 32-bit tick range round-tripping through `clock_gettime()`.
- `tests/test_linux_security_paths.c` — the inputs `linux_security` must refuse: 11 shell payloads per entry point, 12 strings that are not one shell word (with 16 real values that must still be accepted), one hostile `rootfs_dir` per `*_install_to_rootfs`, and the absent-tool and failed-copy cases for every security step. Refusal is asserted by side effect -- a sentinel file a successful injection would create -- rather than by return code, because these functions have several ways to return -1 and only one of them means the guard caught it.
- `tests/test_devicetree.c` — device tree parser suite: happy path, malformed-blob rejection, a sweep over every truncation of a valid blob, and a single-byte corruption sweep.
- `tests/fuzz/` is now wired into the build. The directory was never added by any `add_subdirectory`, so no fuzz target could be built. `fuzz_devicetree` is enabled and calls the real `eos_dt_parse()` API — it previously declared a non-existent `eos_dtb_parse()` and was commented out.
